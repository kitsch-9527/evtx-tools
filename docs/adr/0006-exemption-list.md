# ADR 0006: 豁免清单机制

- **日期**: 2026-09-07
- **状态**: 已接受（grill-with-docs 评审，7 轮决策确认）
- **关联决策**: 修订比对口径的适用边界；与 ADR 0003/0004/0005 的"勿回退"事实并存

## 背景

D 类残留 162 条中约 15-20 条经逐簇取证定性为：解析器深坑（SPP 1004 参数值本身异常）、
消息源未定位（EventLog 6013）、经典二进制源（disk 51、SAM SDDL）、或**基线管线自身
的信息损失**（WER 1001 的 `\\?\` 被 tr/sed 吃成 `\\\`，R5 已 live 取证实证渲染器输出
才是正确的）。这些条目每轮都以 D 类留在 report.diff 中，混在真实分歧里，掩盖新回归
的识别——测量系统的噪声淹没信号。

另一面：比对口径是闭环的"测量基准"，若可以随意豁免，豁免就会被滥用为"修不动的都
豁免"，闭环失去意义。

## 决策

- 建立**豁免清单**（Exemption List）：已定性为不可修/低 ROI/基线侧信息损失的已知
  分歧的受控登记。每条必须含：**根因码**（PARSE / SRC / BIN / RO）、根因描述、
  **关闭条件**（什么情况下摘出硬啃）。登记表存于残留攻坚计划文档。
- 两级实施：
  1. **比对层归一**（仅限"测量系统自身损伤"类，如 WER `\\?\`）：在 06-compare.py
     canon_msg 中双向归一，注释标注缘由与影响条数，可一键关闭。
  2. **白名单登记**（不可修类）：豁免条目在比对器中以显式白名单存在（键 = 通道 +
     provider + event_id + 根因码），每轮报告统计豁免命中数；**关闭豁免开关跑全量**
     是批次验收的固定复核步骤（防止豁免掩盖回归）。
- 豁免条目的摘出条件写死在登记表：满足关闭条件即摘出转硬啃（先例：Ntfs 140
  NTSTATUS、CAPI2 LRM 在评审中被摘出）。
- schema_version 与渲染器不受影响——豁免只存在于比对层，上游渲染保持
  wevtapi 对齐的正确输出。

## 后果

- report.diff 中已知噪声被归一，新回归的识别信噪比提升；代价是比对器多一层
  需要维护注释与开关的逻辑。
- 每轮报告需双读：`diff` 总量（含豁免命中）与"有效分歧"（去豁免后）；两者差值
  即豁免命中数，异常增长说明豁免条目发生了新变化（需人工复核）。
- 豁免不是终点：登记表的关闭条件是这些条目未来转入修复的唯一合法入口。

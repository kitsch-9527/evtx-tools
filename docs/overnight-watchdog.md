# 夜间看护执行协议（23:00–次日 09:00 心跳模式）

> 版本：2026-09-09。目的：让六小时执行计划（docs/six-hour-execution-plan.md）在
> 23:00–09:00 窗口内**无人值守持续执行**，直到全部阶段完成或窗口结束。
> 配套自动化：ZCode 定时任务，每 20 分钟一次心跳（cron `*/20 23,0-8 * * *`）。

## 1. 架构：为什么是心跳而不是单会话马拉松

2026-09-08 夜间首跑的实测失效模式：派发限流卡死会话、子代理完成后会话中断闲置整夜。
单会话马拉松 = 单点故障。心跳模式把"持续执行"拆成20分钟粒度的自愈循环：

```
心跳触发(每20min) → 完成检查(H报告在?) → 并发锁检查(90min过期)
  → 领锁 → 取"第一个缺报告的阶段" → 派发1个子代理(一个阶段) → 编排者核对
  → jj提交+阶段报告落盘 → 删锁 → 退出
```

任何一环死亡（限流/会话中断/子代理超时），下一个心跳从磁盘状态续跑，损失 ≤20 分钟。
状态传递只认磁盘（阶段报告 + jj 提交），不依赖任何会话记忆。

## 2. 每次心跳的执行要点（编排者会话）

0. `date '+%F %T'` 取当前时间；工作目录 E:\Code\evet。
1. **完成检查**：`docs/phase-reports/phase-H-report.md` 存在 → 计划已完成，直接退出。
2. **并发锁**：`docs/phase-reports/.orchestrator-lock` 存在且时间戳距今 <90 分钟 →
   有其他执行会话在跑，退出。锁过期/残留 → 删旧领新（写入当前时间）。
   ⚠️ 锁文件不入库：本轮结束 jj commit 前必须删除它。
3. **执行一个阶段**：读 docs/six-hour-execution-plan.md 与 docs/orchestrator-prompt.md，
   找第一个缺 `phase-X-report.md` 的阶段，派发**恰好一个**子代理
   （模型 glm-5.3-flash；提示词 = 计划 §X 全文 + §5 模板：必读/禁读清单、
   时间盒、退出条件、报告与 jj commit 要求）。子代理返回后核对：
   报告存在且模板完整 / 验收数字达成 / acceptance-check 无 G1/G2 FAIL / jj 已提交。
   核对不过 → 按该阶段退出条件处置（回退重派一次或登记转后续）。
   本轮只做一个阶段，做完即收尾退出。
4. **限流处置**：派发遇速率限制 → 等 5 分钟重试，至多 3 次；仍失败 → 删锁、
   退出（下次心跳续跑）。不硬扛。
5. **墙钟纪律**：本地 ≥07:30 后只允许执行时间盒 ≤30 分钟的阶段（E/F/G/H）；
   ≥08:00 不开新阶段，只收尾（阶段报告与提交落盘、按需更新 final-report.md 终态锚点）；
   ≥09:00 一律停止。
6. **红线一票否决**：Security/Setup diff>0、B/C 新增、缺失类 diff →
   jj 回退该阶段提交 → 重派一次 → 仍失败登记转后续。
   禁读：report.diff 全文、msgdb/new-parsed 下 DB、handoff 全文。
7. **做完 H**：确认 final-report.md 标注全部阶段完成并提交，退出；
   此后心跳自动空转（**用户应删除该自动化**：ZCode 自动化列表里删除即可）。

## 4. 运行前提（用户侧一次性检查）

1. **机器不休眠**：Windows 电源设置改为"睡眠=从不"（接通电源），否则心跳不会触发。
2. **ZCode 保持运行**、本工作区（E:\Code\evet）保持打开；自动化随应用存活。
3. **权限模式放行**：夜间无人值守不能弹权限确认——把本工作区的工具权限
   （Bash/jj/python 等）设为自动允许，或切到 yolo/always-allow 模式。
4. **窗口内不要手动跑编排者**（锁会挡住心跳；人为介入请先删锁）。
5. 配额：子代理消耗 glm-5.3-flash 配额（单阶段实测 ~100 万 token）；心跳机制容忍限流。

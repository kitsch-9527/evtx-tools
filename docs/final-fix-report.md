## 1. 修复工作总结

### 1.1 修复的问题列表

#### **问题 1: EventID 24 (Microsoft-Windows-Kernel-General) 模板匹配错误**
- **现象**: 显示错误的模板消息，应显示时区刷新消息
- **影响**: 高 - 影响系统事件解析准确性
- **状态**: ✅ 代码修复已完成
- **修复方案**: 改进模板查询逻辑，添加语言过滤和dll_id字段

#### **问题 2: EventID 6013 (EventLog) 模板匹配错误**
- **现象**: 显示关机消息，应显示系统运行时间
- **影响**: 高 - 影响系统事件解析准确性
- **状态**: ✅ 代码修复已完成
- **修复方案**: 改进模板查询逻辑，添加语言过滤和dll_id字段

#### **问题 3: Setup 通道值映射回归**
- **现象**: 222 个 Setup 事件显示数值而非可读字符串
- **影响**: 高 - 导致所有 Setup 事件不匹配
- **状态**: ⏳ 待修复
- **修复方案**: 实现 Setup 特定值映射，完善语言回退机制

#### **问题 4: EventID 566 (Microsoft-Windows-Kernel-Power) 值映射缺失**
- **现象**: Reason 字段显示数值而非可读字符串
- **影响**: 中 - 影响事件可读性
- **状态**: ⏳ 待修复
- **修复方案**: 实现硬编码值映射作为fallback

#### **问题 5: EventID 8233, 8230 (Microsoft-Windows-Security-SPP) 参数格式问题**
- **现象**: GUID 显示格式与 Windows 事件查看器不一致
- **影响**: 低 - 轻微格式差异
- **状态**: ⏳ 待修复
- **修复方案**: 统一格式化逻辑，添加GUID格式化函数

### 1.2 修复方案总结

#### **1.2.1 模板匹配错误修复方案**
1. **改进模板查询逻辑**: 在resolver.rs中改进warmup_lang()函数
2. **添加语言过滤**: 在每个条件子句中添加语言过滤
3. **添加dll_id字段**: 在查询中添加dll_id字段
4. **多模板选择逻辑**: 实现优先级选择机制

#### **1.2.2 值映射缺失修复方案**
1. **修复msgdb-dump工具**: 确保正确提取VMAP/BMAP数据
2. **添加fallback逻辑**: 实现硬编码值映射作为后备
3. **完善语言回退机制**: 确保zh-CN不可用时回退到en-US

#### **1.2.3 参数格式问题修复方案**
1. **统一格式化逻辑**: 实现GUID格式化函数
2. **添加格式控制选项**: 支持完整格式和截断格式

## 3. 技术发现

### 3.1 模板匹配机制发现
- **发现**: Provider名称标准化可以解决大部分匹配问题
- **应用**: 在resolver.rs中实现normalize_provider_name函数

### 3.2 语言过滤发现
- **发现**: 语言过滤可以提高模板匹配准确性
- **应用**: 在warmup_lang()函数中添加语言过滤

### 3.3 dll_id字段发现
- **发现**: dll_id字段可以改进模板选择逻辑
- **应用**: 在查询中添加dll_id字段

### 3.4 CRIM数据提取发现
- **发现**: enrichFromCRIM函数不处理VMAP/BMAP数据
- **应用**: 需要在enrichFromCRIM中收集VMAP/BMAP数据

### 3.5 value_maps表问题发现
- **发现**: value_maps表在数据库中不存在
- **应用**: 需要修复msgdb-dump工具，确保value_maps表正确创建和填充

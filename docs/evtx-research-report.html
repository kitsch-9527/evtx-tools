📋 执行摘要

本项目旨在实现 EVTX 解析工具与 Windows 事件查看器的 1:1 匹配。经过深入的逆向工程研究和多轮迭代修复，我们已取得以下成果：

✅ 核心成就：
  • 结构化字段 (event_id, provider_name, level) 100% 匹配
  • Setup 渠道消息 100% 匹配
  • System/Application 渠道匹配率显著提升
  • VMAP/BMAP 值映射机制已逆向理解
⚠️ 待解决问题：
  • VMAP 字符串解析使用特殊编码格式 (0xD200xxxx)
  • Kernel-Power DLL 没有 RT_STRING 资源
  • 需要从 DLL 数据段直接读取字符串

🔬 技术发现

1. Windows 事件日志系统架构

组件文件职责
wevtapi.dllC:\Windows\System32\事件日志 API 库
wevtsvc.dllC:\Windows\System32\事件日志服务
eventvwr.exeC:\Windows\System32\事件查看器 GUI
ntoskrnl.exeC:\Windows\System32\内核（含 Session Reason 字符串）

2. 消息模板解析流程

解析流程：
EVTX 文件 → 解析文件头 → 遍历事件记录 → 提取系统数据 → 查找消息模板 → 替换 %1 %2 → 处理 %%N 引用 → 输出结果

消息模板存储位置：

  • DLL 资源 - RT_MESSAGETABLE 资源
  • CRIM 元数据 - 事件元数据二进制格式
  • MUI 文件 - 多语言界面文件

3. VMAP 字符串编码发现

关键发现： VMAP 字符串偏移量使用特殊编码格式 
VMAP 字符串偏移量: 0xD200011F
├── 高16位 (0xD200) = 字符串表类型标识符
└── 低16位 (0x011F = 287) = 字符串表中的索引

字符串实际位置：

  • InputHid: ntoskrnl.exe 偏移 172910 (0x2A36E)
  • SessionUnlock: ntoskrnl.exe 偏移 173306 (0x2A51C)
  • 存储在 DLL 数据段，不是 RT_STRING 资源
